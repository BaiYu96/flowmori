## 5. 收纳：先验证真实能力，再更换交互

### 5.1 无移动触发探针

复用专用 QA 夹具，分别测试普通菜单、自定义弹窗和右键菜单：

- 图标保持收起，取得对应原应用 AX 元素及支持的动作，验证能否通过实际支持的动作触发。
- 不假定所有状态栏图标都实现同一 AX 动作，不假定触发返回成功就等于菜单出现。
- 同时验证原应用动作事件、菜单/弹窗真实可见、可操作、关闭后状态稳定。
- 高频采样原图标及其他同排图标的 WindowServer 布局，证明激活期间没有先展开或临时拖动。仅比较操作前后坐标不足以排除中间移动。
- 右键能力独立判断：不把普通打开当右键成功，不在屏幕外坐标盲发点击事件。
- 检查弹窗是否仍锚定屏幕外或被刘海遮挡。若动作发生但界面不可访问，应判失败。
- 同一方案失败两次且没有新证据时，停止重复尝试，改做原因分析。

输出最小能力矩阵：菜单类型、可用动作、动作是否执行、界面是否可访问、是否发生图标移动、证据位置。夹具成功不代表全部第三方应用成功；产品需按实际能力处理。

### 5.2 产品行为与内部接口

根据成功探针在现有系统桥接层增加“直接激活能力及结果”，使用明确状态区分：可直接左键打开、可直接右键打开、暂不可用及原因。

- 面板左键调用直接打开；右键菜单中的“右键操作”只在相应能力可用时启用。
- 没有能力时提示“此图标暂不支持在收纳盒内直接操作”，提供显式“展开菜单栏”出口；不要自动展开，更不能静默临时移动。
- 未验证前标为“待检测”，检测必须有边界，不在后台不断触发菜单。
- 保留原有归属确认、源进程存活、系统保护项、权限、锁屏及串行操作检查。
- 激活前重新取得原应用元素，避免复用过期 AX 引用或复用窗口 ID。
- 菜单关闭、源应用退出、超时和取消均释放操作状态，允许继续操作其他图标。
- 不把所有者或类型写死为某款应用，也不复制第三方菜单的外观来冒充原菜单。
- 移除或隔离旧临时拖出/归位路径，使它不再成为面板点击的默认或失败回退。全量收纳、显式手动组织所需的移动仍可保留。
- 诊断信息记录激活方式、阶段和结果，避免继续沿用只有 `moveFailed` 的模糊错误。

### 5.3 原菜单栏图标手动拖入

先验证 macOS 原菜单栏拖动是否能把来源身份和落点可靠交给接收窗口。普通文件拖放注册不等于支持状态栏图标：

- 使用专用夹具测试普通拖动和系统原生支持的修饰键拖动，记录实际可行方式。
- 只有在能够可靠识别来源、跟踪拖动结束并完成原图标收纳时才启用产品接收区。
- 若需要 Command 拖动，界面明确写“按住 ⌘ 拖入”，不伪装成普通拖动。
- 交互目标：打开收纳盒后可拖入；拖到 Flowmori 入口时，若探针证明能够安全检测，则短暂停留自动展开接收区。不能因做不到入口悬停就声称整个功能完成，应记录差异。
- 接收区显示明确高亮；松手后再确认实际布局和收纳成功，确认前不显示成功状态。
- 按 Esc、拖离接收区、来源退出或权限丢失时取消，不能把无关图标移走。
- 系统保护项和归属不明确项拒绝接纳，并提供中文原因；不按名称猜测来源、不仅凭一个坐标决定接纳对象。

若系统无法支持这一输入形式，提交可行性结论，等待用户选择替代方案；不要擅自实现成“未收纳列表拖到已收纳列表”后称为完成。

### 5.4 手动偏好与自动收纳

- 手动接纳使用稳定身份保存偏好，不能持久化 WindowServer ID 或 PID。
- 优先使用应用 bundle ID 与可靠的状态项标识；同应用多图标没有可靠区分标识时，不扩大为全部接纳，记录此限制。
- 新增“移出收纳”操作，成功后保留该图标的手动排除偏好，自动轮询不能立即收回。
- “收纳全部”默认尊重手动排除；需有明确的“重置收纳偏好”操作才能清除，不静默覆盖。
- 原有无偏好的用户继续保留自动接纳新可管理图标的行为。新增偏好版本化存储，读取失败使用安全默认，不损坏现有设置。
- 保持入口在刘海外可见，普通使用不需要用户去拖一个被刘海遮挡的分隔符。

## 6. 截图后立即标注

### 6.1 数据流

将现有流程：

`区域截图 → PNG → 立即复制`

改为：

`区域截图 → 编辑会话（原图 + 标注）→ 明确完成动作 → 合成 PNG → 现有复制/历史或保存/贴图路径`

- `CaptureService` 继续负责选区和原图，不承担全部编辑界面职责。
- 增加独立编辑控制器与画布，在 `AppController` 中把截图回调接入编辑器；删除该回调中的无条件立即复制。
- 原图保留不变，标注为独立对象；导出时渲染一次，不用反复截图编辑窗口的方式合成。
- 编辑状态包括原图像素尺寸、标注对象、选择、当前工具与撤销历史。标注坐标统一使用原图像素坐标，视图缩放通过显式转换处理。
- 同一时间只维护一个截图编辑会话。编辑器打开时再次触发截图快捷键，聚焦现有编辑器并提示先完成或取消，避免静默丢弃内容。

### 6.2 界面与操作

- 选区结束立即显示截图与工具条，避开刘海及屏幕边缘；大图按可用区域缩放展示，不改变原像素尺寸。
- 工具：选择、矩形框、箭头、文字、自由画笔。默认选中矩形，默认红色；提供少量常用颜色及细/中/粗线宽。
- 矩形无填充。拖动可反向绘制；箭头起点到终点；画笔按单次笔划作为一个对象。
- 点击画布添加文字，使用真正的文本编辑控件支持中文输入法、多行与修改。输入法组词时不能把回车误当全局完成。
- 选择工具允许选中、移动和删除标注；矩形和箭头可调整控制点，文字可重新编辑。画笔整条选择移动，不做复杂节点编辑。
- 每次完整绘制、拖动结束、文字编辑确认或删除形成一次撤销操作；支持 Cmd+Z、Shift+Cmd+Z。
- 文本输入时 Delete/Backspace 操作文本，只有画布选中对象时才删除标注。
- Esc 优先结束当前文字编辑或取消当前未完成绘制，再取消整个截图编辑会话。
- 工具按钮设置稳定的辅助功能标签，方便真实 UI 自动化读取。

### 6.3 完成、保存、贴图与取消

- “完成并复制”：确认文字编辑，合成 PNG，写入现有剪贴板和历史路径，然后关闭编辑器。直接按完成且无标注时复制原图。
- “保存…”：导出同一渲染结果，通过系统保存对话框保存 PNG；取消保存对话框返回编辑，不丢失标注；保存成功后保留编辑器。
- “贴图”：通过现有 `PinController` 展示同一合成结果，成功后关闭编辑器；不额外覆盖剪贴板。
- “取消”及关闭编辑器：丢弃本次编辑，不改变此前剪贴板，不写入截图历史。
- 复制、编码、保存失败时保留编辑状态并显示原因，不能提示成功后丢失内容。
- 合成结果不包含工具条、选区边框、对象控制点或窗口阴影。保证原图尺寸、方向和透明区域正确，不因 Retina 或画布缩放产生坐标偏移。
- 截图编辑结束后恢复原应用焦点。调整当前 `CaptureService.cancel()` 的焦点恢复时序，避免进入编辑器前后反复抢焦点。

## 7. 测试：复用脚本，更新断言，不重跑无关模块

### 7.1 自动测试

在现有测试结构内增加必要回归覆盖：

- 激活能力分流：支持、暂不支持、源退出、权限失效；不会暗中进入旧拖动路径。

- 一次笔划一次撤销、文字编辑/删除的撤销重做、取消不提交。
- 固定合成样例验证图像尺寸与关键区域颜色，不仅测试“能生成非空 Data”。

不要为每个 UI 属性编写镜像测试。按实际测试类名执行相关过滤测试；现有 `scripts/swift-command.sh` 可复用。出现失败、代码再次修改或有新增风险时才补跑。

### 7.2 原生 UI 验收

本地自动化不是单纯构建测试：使用 `scripts/qa/run.py`、包外 `.validation/FlowmoriQAHelper` 和专用夹具控制真实桌面。OpenCode 的执行宿主与产品各自需要 macOS 权限；不因为另一个宿主已授权就假定它也已授权。

- 先核实当前 PID、诊断心跳时效及两项权限。必要时重开同一个安装包并传 `--diagnostics`，不重新签名。
- 原脚本 `menu-acceptance.py` 以临时移动再归位为背景，必须更新为直接激活断言；保留历史脚本/证据供对照，不能把旧验收通过当新体验通过。
- 三类夹具操作均要求：真正触发、界面可访问、动作完成、隐藏状态稳定至少 4 秒；激活期间布局采样证明没有临时移出。
- 测试手动拖入、取消、移出、重启偏好、新图标自动接纳及系统保护项拒绝。系统项只做读取/策略检查，不实际拖动系统控制。
- 截图只针对专用测试文档：画红框、中文文字、箭头、笔划，执行撤销重做，核对复制、保存与贴图合成结果一致；验证取消后剪贴板不变。
- 不读取其他业务文档，不打开其他应用业务菜单。锁屏立即停止输入，不自动解锁，不修改 TCC。

- 两小时稳定监测仅在最终交互通过后运行一次，使用现有 `scripts/soak.py`。它只证明运行、心跳、CPU/RSS，不证明菜单交互正确；未满时长不得标完成。
